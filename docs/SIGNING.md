# TSWA signing — how it works

## Standing rule (Rob, 2026-11-21)
When Muse creates an Android app for Rob, **Muse generates the signing
keystore and its password** and hands them over to Rob. Rob's jobs are:
keep backups, and paste four values into GitHub Secrets (below).

## The one-paragraph version
An Android *release* build must be signed with a private key. Google Play
and Android itself identify the app by that key: every update must be
signed with the **same** key, forever. If the key is lost, the app can
never be updated under the same listing. So it is generated once, backed
up in two places, and never committed to git (`.gitignore` blocks it).

## TSWA's key
- File: `tswa-release.jks` (PKCS12 format, RSA 2048, alias `tswa`,
  validity ~27 years), generated by Muse with OpenSSL on 2026-11-21.
- One password protects both the store and the key (PKCS12 style).
- Muse keeps a copy in a private, non-git folder on the VM; Rob keeps
  the backups that count (password manager + a second safe place).

## Concepts
- **Debug signing**: Android auto-generates a throwaway debug key. Debug
  APKs install fine for testing the UI on your own phone — no setup.
- **Release signing**: only needed to share the app properly (Play, or
  APKs other people install and later update).

## Give GitHub Actions the key (Secrets)
Repo Settings -> Secrets and variables -> Actions -> New repository secret:

| Secret name              | Value                                          |
|--------------------------|------------------------------------------------|
| `TSWA_KEYSTORE_BASE64`   | the keystore file, base64-encoded (see below)  |
| `TSWA_KEYSTORE_PASSWORD` | the password Muse generated                   |
| `TSWA_KEY_ALIAS`         | `tswa`                                         |
| `TSWA_KEY_PASSWORD`      | same password (PKCS12 uses one)                |

Base64-encode the keystore on your machine:
- macOS: `base64 -i tswa-release.jks | pbcopy`
- Linux: `base64 -w0 tswa-release.jks > tswa-release.jks.b64`, paste the
  single line as the secret value.
- Windows (PowerShell):
  `[Convert]::ToBase64String([IO.File]::ReadAllBytes("tswa-release.jks"))`

Once all four secrets exist, every workflow run also produces a signed
release APK. Until then, runs produce the debug APK only — all we need
for UI work.

## Installing builds on your phone
1. Open the repo's **Actions** tab, pick the latest successful run.
2. Download the `tswa-debug` artifact (a zip containing `app-debug.apk`).
3. Open the APK on the phone and allow "install unknown apps" for the
   browser/files app when Android asks, just for this install.
4. Debug builds can be installed over the top of earlier debug builds.
